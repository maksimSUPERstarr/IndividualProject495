## Назначение и пользователи

Программа помогает координатору назначать руководителей проектов с учётом
их специализации, доступности и загрузки. Решение принимает координатор,
а сервис проверяет ограничения и сохраняет результат.

Пользователи — координаторы проектов и руководители подразделений.
Учётные записи и веб-интерфейс будут добавлены на последующих этапах.

## Предметная область и правила

Основные сущности: проект, руководитель и назначение. В ПР2 они представлены
**списками словарей**. Собственные классы на этом этапе не используются.

Подтверждённое пользователем правило: координатор назначает руководителя
с учётом специализации и загрузки. Принятые в прототипе уточнения:

- У проекта может быть одно действующее назначение.
- Направление проекта и специализация руководителя должны совпадать.
  Регистр и пробелы по краям не учитываются.
- Руководитель должен быть доступен для новых назначений.
- Число его действующих назначений должно быть меньше индивидуального лимита.
- Отмена сохраняет историю и освобождает место в лимите.
- Повторное назначение возможно после отмены предыдущего.
- Координатор подтверждает назначение и отмену ответом `да`.

Загрузка **вычисляется по назначениям**, а не хранится отдельным числом.
Поэтому её не нужно вручную увеличивать или уменьшать в нескольких файлах.

## Формат данных и сохранение

`data/app_data.json` содержит три списка:

- `projects`: `id`, `name`, `specialization`;
- `managers`: `id`, `name`, `specialization`, `project_limit`, `is_active`;
- `assignments`: `id`, `project_id`, `manager_id`, `assigned_on`,
  `is_cancelled`, `cancelled_on`.

Назначение ссылается на проект и руководителя через числовые ID.
Даты записываются строками ISO, например `2026-10-16`.
При действующем назначении `cancelled_on` равно JSON-значению `null`.

Один файл позволяет сохранить все связанные коллекции за одну операцию.
После изменения программа проверяет структуру и связи, полностью записывает
временный файл и заменяет основной. Изменения принимаются в памяти после
успешного сохранения. При отказе записи прежние данные сохраняются.

Если файла нет, программа открывает пустые коллекции. Если JSON повреждён,
имеет неверные типы, потерянные связи, повторные ID или нарушает ограничения,
программа показывает причину и завершается, не перезаписывая исходный файл.

## Установка и запуск

Для программы достаточно стандартной библиотеки Python. Рабочее окружение
ПР1 использует Python 3.14.7; код написан с учётом Python 3.11 и новее.
Перед ПР5 версию окружения следует сверить с указанием Python 3.11 в методичке.

В PowerShell из каталога проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Если `.venv` уже создано, пересоздавать его не требуется.
В VS Code можно выбрать `.venv\Scripts\python.exe` и нажать F5,
конфигурация «ПР2: консольное меню».

Путь к стандартному JSON вычисляется относительно `storage.py`, поэтому
приложение можно запускать из другого рабочего каталога. Для отдельного
хранилища укажите путь:

```powershell
.\.venv\Scripts\python.exe main.py --data data/my_data.json
```

Новый файл начнётся с пустых коллекций. Используйте пункты 4 и 5 для их
заполнения. Для проверки учебного сценария на копии:

```powershell
Copy-Item data/app_data.json data/practice.json
.\.venv\Scripts\python.exe main.py --data data/practice.json
```

## Тестирование и качество кода

```powershell
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m flake8 .
```

48 тестов проверяют ограничения назначения, отбор и сортировку, отмену,
загрузку, сохранение, повреждённые данные, отказ записи и все пункты меню.
Рабочий JSON не изменяется: для файловых проверок pytest использует
собственные временные каталоги.

Аннотации основных функций описывают параметры и результаты. `Record`,
`Records` и `AppData` — обозначения типов словаря, списка словарей и
совокупности коллекций, а не новые классы.
