## Назначение

Сервис помогает координатору назначать руководителей проектов с учётом
их специализации и текущей загрузки. Решение о назначении принимает
координатор, а программа проверяет допустимость назначения.

## Целевая аудитория

Координаторы проектов и руководители проектных подразделений. На следующих
этапах руководители смогут просматривать свои назначения.

## Предметная область

Проект имеет название и направление. Руководитель имеет специализацию,
текущую загрузку и индивидуальный лимит одновременно выполняемых проектов.
Координатор выбирает кандидата, проверяет ограничения и подтверждает
назначение. Успешное назначение связывает проект с руководителем и
увеличивает его загрузку на один проект.

Подтверждённое пользователем правило: координатор назначает руководителя
с учётом специализации и загрузки.

Принятые для прототипа допущения, которые можно уточнить при согласовании:

- У проекта может быть один действующий руководитель. Повторное назначение
  запрещено; переназначение будет отдельной операцией в будущем.
- Специализация должна совпадать с направлением проекта. Регистр букв и
  пробелы по краям не учитываются; синонимы пока не обрабатываются.
- Назначать можно только доступного руководителя с загрузкой ниже лимита.
- Лимит задаётся отдельно для руководителя. Число 3 в демонстрации является
  учебным значением, а не обязательным правилом темы.
- Подтверждением считается ответ `да` без учёта регистра и пробелов по
  краям. Любой другой ответ отменяет операцию.

## Основные сущности

- **Проект (Project):** название, направление, назначенный руководитель.
- **Руководитель (Manager):** имя, специализация, доступность, загрузка,
  лимит проектов.
- **Назначение (Assignment):** связь проекта и руководителя, дата назначения.
- **Координатор:** пользователь, подтверждающий назначение; учётные записи
  будут добавлены на дальнейших этапах.

На ПР1 эти данные представлены простыми переменными. Классы и коллекции
будут введены в соответствующих практических работах.

## Основные функции

Реализованы три функции предметной области:

| Функция | Что делает |
| --- | --- |
| `specializations_match()` | Проверяет совпадение непустых специализаций. |
| `has_free_capacity()` | Проверяет, есть ли место для ещё одного проекта. |
| `get_assignment_rejection_reason()` | Объединяет проверки и объясняет отказ; возвращает пустую строку, если назначение допустимо. |

Функция `main()` показывает учебные данные, получает подтверждение
координатора, назначает руководителя и увеличивает загрузку.

## Реализованный сценарий ПР1

1. Программа показывает проект «Корпоративный портал задач» и кандидата
   Анну Смирнову. У обоих направление «Веб-разработка».
2. Проверяется отсутствие прежнего назначения, доступность руководителя,
   корректность загрузки, совпадение специализаций и наличие свободного места.
3. При отказе выводится конкретная причина. Подтверждение не запрашивается.
4. Если проверки пройдены, координатор вводит `да` или отменяет назначение.
5. При подтверждении руководитель назначается, загрузка увеличивается
   с 2 до 3, выводятся дата и результат операции.

Результат хранится в памяти до завершения программы. При следующем запуске
снова используются исходные учебные данные. JSON-хранилище относится к ПР2.

## Установка и запуск в Windows PowerShell

Откройте терминал в каталоге проекта. Проверьте Python и создайте окружение:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Запустите приложение:

```powershell
.\.venv\Scripts\python.exe main.py
```

Введите `да`, чтобы выполнить назначение, или `нет`, чтобы отменить его.
Запуск через полный путь к интерпретатору окружения не требует изменения
политики выполнения PowerShell.

ПР1 не фиксирует конкретную младшую версию Python. Код написан с учётом
Python 3.11 и новее. В методичке ПР5 указан Python 3.11; перед переходом
к этому этапу версию окружения следует согласовать с требованиями курса.
