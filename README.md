# Сервис назначения руководителей проекта

Индивидуальный проект по теме № 495. Координатор подбирает руководителя
с учётом специализации, доступности и текущей загрузки.

Автор: **Поберем Максим Станиславович**, группа **ЭФБО-12-24**.

Текущий этап — **ПР5: Django, HTTP и основы веб-разработки**. Веб-интерфейс
дополняет рабочую консольную версию. Отчёт ПР5 пока не оформляется.

## Возможности

- Обзор проектов без руководителя, действующих назначений и свободных мест.
- Каталог проектов: поиск, фильтр неназначенных проектов, карточка проекта.
- Подбор руководителей по общим правилам консольной версии, сортировка
  кандидатов по нагрузке.
- Справочник руководителей: поиск, фильтр доступности, нагрузка и история.
- История назначений: действующие и отменённые записи, связанные карточки.
- Предметные страницы 404 и общий обработчик неизвестных адресов.
- Изменение данных через прежнее консольное меню с сохранением в JSON.

## Быстрый запуск на подготовленном компьютере

В корне проекта запустите `start_web.bat`, дождитесь запуска сервера
и откройте <http://127.0.0.1:8000/>. Скрипт использует `.venv`, применяет
служебные миграции Django и запускает локальный сервер. Остановка — `Ctrl+C`.

В VS Code можно открыть папку проекта и выбрать конфигурацию
**«ПР5: Django»**, затем нажать `F5`.

## Установка с нуля

Нужны Python 3.11 или новее и Git. Команды для PowerShell из корня проекта:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver
```

Активация окружения необязательна: команды явно используют его интерпретатор.
Если установлен другой поддерживаемый Python, используйте его для создания
окружения. Локально проект проверен на Python 3.14.7 и Django 5.2.18.
В `requirements.txt` ограничена ветка Django: `Django==5.2.*`.

SQLite содержит только служебные таблицы встроенных приложений Django.
Проекты, руководители и назначения в ПР5 загружаются из `data/app_data.json`.
Создавать администратора для просмотра страниц не требуется.

## Страницы и представления

| URL | Представление | Назначение |
| --- | --- | --- |
| `/` | `homepage.views.index` | Обзор и подбор для свободных проектов |
| `/projects/` | `project_pages.views.project_list` | Список проектов |
| `/projects/<int:project_id>/` | `project_pages.views.project_detail` | Карточка и кандидаты |
| `/managers/` | `manager_pages.views.manager_list` | Руководители и загрузка |
| `/managers/<int:manager_id>/` | `manager_pages.views.manager_detail` | Карточка руководителя |
| `/assignments/` | `assignment_pages.views.assignment_list` | История назначений |
| `/assignments/<int:assignment_id>/` | `assignment_pages.views.assignment_detail` | Карточка назначения |

Списки проектов и руководителей принимают параметр поиска `q`.
Поддерживаются фильтры `?status=unassigned` для проектов,
`?status=available` для руководителей, `?status=active` и
`?status=cancelled` для назначений. Фильтры передаются методом GET.

Корневой `config/urls.py` подключает URLconf приложений через `include()`.
Маршруты имеют пространства имён `homepage`, `projects`, `managers`,
`assignments`. Ссылки формируются функцией `reverse()`. Обработчик
`handler404` зарегистрирован в корневом URLconf.

## Структура

```text
manage.py                   Управление Django
config/                     settings.py, urls.py, asgi.py, wsgi.py
homepage/                   Обзор, общий HTML, оформление и обработчик 404
project_pages/              URL и view-функции проектов
manager_pages/              URL и view-функции руководителей
assignment_pages/           URL и view-функции назначений
models/                     Обычные Python-классы, не Django ORM
    projects.py             Project
    managers.py             Manager
    assignments.py          Assignment со ссылками на Project и Manager
    catalog.py              Catalog: снимок данных и общие правила
storage.py                  JSON: чтение, проверка и атомарная запись
validation.py               Проверка полей, ссылок, дат и ограничений
rules.py                    Правила ПР1
projects.py                 Консольные операции над проектами
managers.py                 Консольные операции над руководителями
assignments.py              Назначение, отмена, загрузка и подбор
main.py                     Консольное меню ПР2
data/app_data.json          Общие данные консоли и веб-интерфейса
tests/                      Прежние тесты и проверки классов/HTTP
docs/                       Материалы предыдущих практических работ
start_web.bat               Запуск локального веб-сервера на Windows
```

Четыре Django-приложения зарегистрированы в `INSTALLED_APPS`.
Руководитель — предметный объект, а не учётная запись Django `User`.
Регистрация и аутентификация пользователей на этом этапе не реализуются.

## Объектная модель и общие правила

Готовой версии ПР3 в исходном репозитории не было. По согласованию с автором
перед Django добавлены необходимые обычные классы `Project`, `Manager`,
`Assignment` и связанный снимок `Catalog`. Это подготовка к ПР5, а не
подтверждение отдельного выполнения и сдачи всех заданий ПР3.

`load_catalog()` вызывает прежнюю функцию `load_data()`, проверяет данные
и восстанавливает связи: `assignment.project` и `assignment.manager`
ссылаются на те же экземпляры, что находятся в каталоге. Даты представлены
объектами `date`. `Catalog.to_data()` возвращает совместимые записи JSON.

Веб-слой использует атрибуты объектов. При расчёте загрузки, проверке
назначения и подборе кандидатов `Catalog` вызывает существующие функции
`assignments.py`. Правила совпадают с консольной версией:

1. У проекта не больше одного действующего назначения.
2. Специализации должны совпадать без учёта регистра и пробелов по краям.
3. Руководитель должен быть доступен для новых назначений.
4. Число действующих назначений должно быть меньше личного лимита.
5. Отмена сохраняет историю и освобождает место в загрузке.

Каждый HTTP-запрос читает свежий снимок JSON. Изменения из консоли появляются
при следующем запросе. Операции записи по HTTP отклоняются с кодом 405;
поддерживаются GET и HEAD. Формы создания, изменения и удаления данных
относятся к следующим этапам курса.

Если JSON повреждён или недоступен, веб-интерфейс возвращает 503 с понятным
сообщением и не перезаписывает файл. Отсутствующий файл трактуется как пустое
хранилище, как и в консоли. Совместное редактирование из нескольких процессов
в текущем учебном JSON-хранилище не предусматривается.

## HTML и оформление

Следуя методичке ПР5, `page(title, content, section)` в
`homepage/presentation.py` формирует общий HTML-каркас: `head`, кодировку,
`viewport`, навигацию, подключение Bootstrap 5.3.8 и подвал. Представления
передают содержимое страниц. Общий CSS находится в `homepage/styles.py`.

Используются классы Bootstrap `container`, `nav`, `badge` и собственные стили.
Bootstrap подключён через CDN; собственные стили сохраняют читаемость
при отсутствии интернета. Полноценные Django-шаблоны и ORM оставлены для
следующего этапа, как предусмотрено методичкой. Текст из JSON и GET-параметры
экранируются перед включением в HTML.

## Проверка ошибок 404

`/projects/999/`, `/managers/999/` и `/assignments/999/` возвращают
предметную страницу с HTTP-статусом 404 при любом значении `DEBUG`.
Нечисловой ID не проходит конвертер `<int:...>`.

Общий `handler404` для неизвестного адреса Django показывает при
`DEBUG=False`. Для проверки в отдельном терминале:

```powershell
$env:DJANGO_DEBUG = "0"
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
# Открыть http://127.0.0.1:8001/nonexistent/
# После остановки сервера вернуть режим разработки:
Remove-Item Env:DJANGO_DEBUG
```

`ALLOWED_HOSTS` ограничен `127.0.0.1` и `localhost`. Режим разработки включён
по умолчанию. Также поддерживаются переменные `DJANGO_SECRET_KEY`,
`DJANGO_ALLOWED_HOSTS` и `PROJECT_DATA_FILE`. Последняя позволяет указать
отдельный JSON для демонстрации, не меняя рабочие данные.

## Проверки

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe -m flake8 .
.\.venv\Scripts\python.exe -m pytest -v
```

82 теста проверяют прежние консольные операции, хранение и правила,
связи объектов, загрузку данных, все основные страницы, фильтры, статусы,
HTTP 404/405/503, экранирование HTML и обновление после записи из консоли.
Тесты используют независимые временные JSON-файлы.

Если Windows ограничивает доступ к системной временной папке, можно явно
выбрать новую доступную папку для запуска:

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp=./test-tmp
```

Папка `test-tmp` предназначена только для тестов: pytest очищает её при запуске.

## Демонстрация ПР5

1. Запустить `manage.py check` и сервер, открыть главную страницу.
2. Открыть `/projects/1/`: увидеть двух кандидатов, Марию перед Анной
   по текущей загрузке. Олег недоступен, Иван имеет другую специализацию.

4. Открыть `/managers/1/`: показать нагрузку 2 из 3 и связанные назначения.
5. Открыть `/assignments/1/`: перейти по ссылкам к проекту и руководителю.
6. Проверить поиск, фильтры, несуществующие ID и неизвестный URL.
7. Показать цепочку URLconf → view → загрузка JSON → объекты → `page()`
   → `HttpResponse`, затем тесты и историю Git с префиксом `PR5:`.
